# IAM v2.4.0

This release adds granular Module Version and Pin permissions.

## What changes

- Separate catalogue discovery from version definitions, history and comparison.
- Register publication, promotion, deprecation, Defective marking, restoration,
  Proposed-version use and Pin-related capabilities.
- Preserve Project and Environment scope checks for Pin actions. A currently
  authorised principal can manage a Pin created by somebody else.
- Map existing legacy Module grants only to their equivalent capabilities.
  Do not grant unrelated lifecycle or recovery powers as a side effect.

## Administrator actions

Review custom roles before upgrading automation. A missing version-read
permission means history is unavailable to that caller, not that no history
exists. Assign new powers explicitly rather than granting organisation Admin
just to bypass a failed check.

Legacy `module_read` satisfies catalogue and version read permissions.
Organisation-scoped `module_write` preserves publication, promotion and archive
authority at that scope. It does not grant deprecation, Defective marking,
restoration, Proposed use, Pin control or restricted recovery.

Deploy with CP 3.0.0 and DP 3.2.0. The corresponding Console is
1.3.0; CLI and Terraform/OpenTofu provider are 2.0.0.

## Go contract

The additive shared contract is published separately as `shared/v1.1.0`
under `github.com/stellwerk-labs/platform-orchestrator-iam/shared`.
This module requires Go 1.26.2. Existing compatible consumers can continue to
use the earlier shared module; a root application tag does not publish an SDK.

Preserve IAM data and existing grants during the
coordinated upgrade, and verify custom-role behavior before reopening automation.
