# IAM v2.7.0

Browser sessions expire after genuine user inactivity. New installations default
to a 15-minute idle window and a 2-hour fixed CLI device-login token lifetime.
Browser sessions retain their independent 24-hour absolute limit; polling does
not renew activity. Service-user, Runner and plugin workload policies retain
their existing behavior.

Installation settings expose persisted session policy with revision-based
`If-Match` writes, exact Console origin checks for cookie writes and operator
audit records. Explicit human user UUID grants in `PLATFORM_SETTINGS_READERS`
and `PLATFORM_SETTINGS_WRITERS` control access. Organization roles and service
identities cannot grant themselves this authority. Policy changes immediately
prune expired sessions and apply to remaining user sessions without reviving
expired credentials. Restarts preserve saved policy; environment values seed
new installations only unless the explicit reset option is enabled.

Upgrade and recovery: back up the IAM database and upgrade all IAM replicas,
the matching Console and Core Helm routes together. Migrations 40 and 41 advance
schema 39 to 41. Existing browser sessions are backfilled from creation time and
may require another sign-in immediately. Permit `X-Session-Activity` only from
the exact Console origin. Plugin frames require the additive physical-input
activity message to renew activity. Do not depend on an older binary to reverse
persisted policy or session pruning; preserve verified backups and use tested
restore or forward recovery. Runtime policy writes can briefly lock session
records and have a 30-second deadline.

Security: official builds use Go 1.26.11 and patched HTTP dependencies. Existing
source, executable, content, provenance and signature gates remain in force.
The published IAM shared SDK remains 1.3.0; browser lifecycle/settings contracts
are provided as their own typed OpenAPI documents.
