# IAM 2.8.0

PostgreSQL transport security is configurable through `DATABASE_SSLMODE`. The default remains `disable`; set `require` to enforce encryption without plaintext fallback, or `verify-full` with `PGSSLROOTCERT` to verify the server certificate and hostname. The existing driver handles certificate settings and rejects invalid modes during database initialization.

Connection-string values are quoted correctly, including spaces, quotes and backslashes in credentials or database names. Startup and automatic migrations use the same connection string. The separate authorization migration command retains its existing explicit database URL precedence and `DATABASE_SSLMODE` support.

No database migration or authentication/session behavior change is introduced. Restart IAM after changing database startup settings.

## Breaking authorization change: dedicated deployment log permission

`deployment_logs_read` controls decrypted Runner log contents independently of
deployment metadata. It accepts explicit grants at organization, project and
environment scope. Organization Admins retain access through `manage_all`;
Viewer, Deployer, `read_all`, `write_all` and `deployment_read` alone do not grant
log access. Custom roles and ordinary service users can receive the exact grant.
Existing Viewer, Deployer and wildcard-only custom-role users lose decrypted log
access when the matching Control Plane and Data Plane enforce this permission.
Grant `deployment_logs_read` explicitly to roles and service users that need it.
No authorization database migration is required. Upgrade IAM 2.8.0 before
Control Plane 4.1.0 and Data Plane 4.4.0 enforce the new permission.
