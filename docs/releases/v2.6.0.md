# IAM v2.6.0

Canonical organization Admin verification and immutable built-in role identity.

## Changes

- Add the optional canonical organization Admin API and consume the published IAM
  shared SDK v1.3.0, preserving existing mandatory SDK interfaces.
- Verify current organization-wide membership in the immutable built-in Admin
  role. A custom role with all granular permissions does not become an Admin.
- Preserve built-in role identity across display-name changes and fail closed for
  ambiguous historical/custom roles, revoked membership and unsupported authority.

## Upgrade and recovery

This release advances IAM database schema 38 to 39. Migration classifies historical
built-in roles only from exact seed evidence and records immutable builtin keys.
Back up the IAM database and use the coordinated compatible Core release set.
Apply this IAM migration before enabling consumers that require canonical Admin
verification. Older IAM cannot satisfy that new predicate; such consumers deny
rather than infer Admin status from role names or permissions.

Downgrade refuses to erase populated canonical role identities. Preserve verified
backups and use tested restore/forward recovery rather than assuming a binary
rollback reverses the migration. Existing ordinary authentication and unrelated
endpoint policies retain their behavior. This API grants neither plugin licences
nor registry access.

## Security qualification

For this coordinated release, the documented remaining findings in the selected
ORAS/Cosign tools and the Runner's bundled OpenTofu are accepted after an upstream
recheck. IAM's own source and executable checks remain strict; this exception
does not suppress IAM findings.
